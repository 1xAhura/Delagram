# Delagram

A small key-value store that uses a private Telegram channel as its storage backend and exposes it as a REST API. There is no disk database: every key is a message in the channel, the full index lives in memory, and process restarts rebuild state by scanning the channel history. The channel *is* the database.

It was built as a zero-infrastructure storage layer for a single consumer service: no DB server to run, and durability and off-site backup are delegated to Telegram.

## How it works

- Every key is one message in the channel, stored as plain text: `key: value`.
- `set` sends a new message, or edits the existing one in place. The channel grows with the number of *keys*, not the number of writes.
- The full dataset is held in memory as `{key: (message_id, value)}`. `get` is a dict lookup and never touches the network.
- On startup, the index is rebuilt by walking the channel history oldest-first; the last message per key wins.
- Writes are serialized with an `asyncio.Lock`, so concurrent requests for the same key cannot create duplicate messages.
- One process, one event loop: uvicorn and the Telethon client share it, which is why the Telegram client is started inside the FastAPI lifespan, not at import time or via `asyncio.run()`.

## Requirements

- Python 3.10+
- A Telegram account
- A private channel where that account is an admin

## Installation and first run

```bash
pip install -r requirements.txt
```

1. Get an `API_ID` and `API_HASH` at [my.telegram.org](https://my.telegram.org).
2. Create a private channel and note its numeric ID (e.g. `-1001234567890`). Forwarding a message from the channel to `@userinfobot` is one quick way to get the ID.
3. Start the server with your credentials:

```bash
python main.py --api-id 12345 --api-hash abcdef123456 --channel-id -1001234567890
```

The flags are written to `.env` next to `config.py` and only need to be passed once. The first run prompts for a phone number and login code, then saves the session to `anon.session` in the working directory; subsequent runs are non-interactive. After login, the index is rebuilt and the server starts listening.

## Configuration

Values are stored in `.env` (created by `config.py`) and can also be set directly.

| Variable | Required | Description | Example |
| -------- | -------- | ----------- | ------- |
| `API_ID` | yes | Telegram API id from my.telegram.org | `12345` |
| `API_HASH` | yes | Telegram API hash | `abcdef1234...` |
| `CHANNEL_ID` | yes | Numeric ID of the channel used as storage | `-1001234567890` |

## Running

```bash
python main.py
# serves on http://127.0.0.1:8000
```

or, to control the bind address and port:

```bash
uvicorn main:app --host 127.0.0.1 --port 8000
```

The default bind is loopback. If the service consuming the API runs on another machine, pass a different `--host` and restrict the port at the firewall — the API has no authentication.

Interactive API docs are served at `/docs`.

## API

| Method | Path | Description |
| ------ | ---- | ----------- |
| `GET` | `/health` | Liveness check; returns current key count |
| `GET` | `/kv/{key}` | Read a value |
| `PUT` | `/kv/{key}` | Create or replace a value (upsert) |
| `DELETE` | `/kv/{key}` | Delete a key |

`PUT` takes a JSON body: `{"value": "..."}`.

```bash
curl -X PUT http://127.0.0.1:8000/kv/greeting \
    -H 'Content-Type: application/json' -d '{"value":"hello"}'
# {"key":"greeting","value":"hello"}

curl http://127.0.0.1:8000/kv/greeting
# {"key":"greeting","value":"hello"}

curl -X PUT http://127.0.0.1:8000/kv/greeting \
    -H 'Content-Type: application/json' -d '{"value":"world"}'
# {"key":"greeting","value":"world"}

curl -X DELETE http://127.0.0.1:8000/kv/greeting
# 204 No Content
```

Error responses:

- `404` — key not found (GET, DELETE)
- `400` — key or value rejected by the store: empty, or `:` in the key (the storage format is `key: value`)
- `422` — request body does not match `{"value": <string>}`; generated by request validation before the handler runs
- `500` — Telegram-side failure, e.g. key + value exceeding Telegram's 4096-character message limit

## Project structure

```
main.py          FastAPI app: lifespan starts the Telethon client and rebuilds
                 the index; defines the /health and /kv routes
store.py         TeleDB: in-memory index, get/set/delete mapped to channel messages
serialize.py     Parses "key: value" message text into (key, value)
config.py        CLI flags -> .env persistence, credential loading
requirements.txt Dependencies
anon.session     Telethon session, created on first login
.env             Credentials, written by config.py
```
